# 카드·문제 품질 기준

카드 (매일 새로 만드는 것, 지금 있는 것) 와 퀴즈 앱이 카드로 만드는 문제의 기준. 2026-11-17 사용자 결정: QA 에서 찾은 문제를 여기 다 적고, 지금 카드 고치기와 앞으로 만드는 카드에 같이 적용.

- 근거: 앱 저장소 (language-quiz) `docs/question-review-2026-11-17.md` (검토자 5명이 550문제를 학습자 입장에서 풀어 봄 + 전체 카드 셈), `docs/question-quality.md` (11-04 검수)
- 같이 보는 규칙: 오답 `docs/options.md`, 한국어 번역 `docs/translation.md`, 단계 `routine_prompt.md` 2번
- 새 문제를 찾으면 줄을 더함. 번호는 지우지 않고, 안 쓰게 되면 상태를 `철회` 로
- 2026-11-24 검사 세션이 표본 200장을 판정 (앱 DB `card_reviews` run `2026-11-24-sample`), 사용자가 그중 30장을 손으로 확인: 판정 31개 중 24개 동의, 7개 불동의, 통과 카드 10장은 다 동의. 불동의와 사용자 메모로 오답-03·04·05·06, 정답-02, 내용-01, 설명-02 를 고침

## 읽는 법

- 방식: **기계** = 스크립트가 셈 (`content/card_check.py`, `content/options_check.py`, 앱 코드). **판단** = 카드 만드는 Claude 가 다시 읽고 확인, 검사 세션이 표본으로 확인
- 매일 검사 (2026-11-24 사용자 "키자 허락할게"): 09:30 KST 검사 작업이 그날 새 카드의 판단 항목을 판정 (`card_reviews` run `daily-날짜`). 다음 날 아침 카드 작업이 `flagged` 로 걸린 카드를 받아 `fix-cards` 로 고침 (`routine_prompt.md` 7번). 표현·단계·분류는 여기서 안 바꿈
- 거부: 쓰기 전 검사 (`python daily_notion.py lint`) 와 쓰기 (`write`, `add-options`) 가 받지 않음. 경고: 받되 보고
- 지키는 곳: **생성** = 매일 카드 만들 때, **앱** = 앱이 문제 만들 때, **지금 카드** = 이미 있는 카드 고칠 목록 (DB 반영은 사용자 승인 뒤)
